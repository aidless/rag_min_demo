# 混合检索与融合重排

单一检索方式各有盲区。稠密向量检索擅长语义匹配，但对专有名词、型号、代码符号这类低频但精确的 token 表现不稳；BM25 这类稀疏检索恰好相反，它靠词频和逆文档频率打分，对罕见词很敏感，但完全不理解同义表达。混合检索的做法是同时跑两路，各自取一批候选，再把两路分数融合成一个排序。

融合的关键不在于加权求和本身，而在于两路分数的量纲不同。向量余弦相似度落在 -1 到 1 之间，而 BM25 分数是无上界的正数，常见值域在 0 到 15 之间。直接按固定权重相加会让 BM25 完全压制余弦，即使你以为两个权重各占一半。标准做法是在各自候选集内做最大归一化，把分数除以该路候选里的最高分，映射到 0 到 1 之后再加权。权重取 0.6 偏稠密、0.4 偏稀疏是一个常见起点，但这个取值必须实测。

融合之后还可以接重排。打分阶段追求召回，用便宜的方法取前 20 到 50 个候选；重排阶段追求精度，用更贵的模型对这几十个候选重新打分，取前 3。重排模型通常是交叉编码器，它把查询和文档拼在一起送入模型，能建模两者之间的细粒度交互，而双编码器只能分别编码后算相似度。代价是重排的计算量随候选数线性增长，无法预计算。

常见误区是把融合权重当成超参数随意调优。权重在一个语料上调到最优，换到另一个语料上往往不再最优，因为它反映的是该语料里稀疏信号与稠密信号的相对强度。更稳妥的做法是把权重当作需要随语料重新标定的部署参数，在每次换数据集时用一个小验证集重跑一次，并把标定结果记进配置。
