# 查询路由

查询路由要回答的问题是：同一个检索系统里，不同类型的查询是否需要不同的处理路径。闭集问答的答案通常就在某一处，上下文里能找到明确的定义段落，直接检索就能解决。摘要型查询需要跨多处收集信息再组织，检索到单一片段往往不够。比较型查询需要同时召回被比较的两方，只召回到一方等于答错。拒答型查询的正确行为是承认资料里没有，而不是强行从最相似的片段里编一个答案。

不区分查询类型就用同一套参数，是最常见的配置错误。一条"X 和 Y 有什么区别"的查询，用 top-1 的截断参数去答，召回窗口太窄，第二方根本没进上下文；用 top-10 又会引入噪声。对这类查询，正确的配置是分别召回两方各自的前若干个，然后合并成结构化对比，而不是把所有结果平铺给模型自己分辨。拒答类查询则需要先判断证据强度，证据不足时直接返回"没有找到"，而不是降低阈值继续检索。

路由的判别依据可以是查询的形式特征，也可以是查询与文档的初始匹配情况。前者实现简单，靠规则或小分类器，成本低但边界模糊，一条查询常常同时具备两种查询类型的特征。后者依赖一个先行的廉价检索，用初始 top-1 的分数分布来判断：分数集中说明文档里答案明确，分布平坦说明可能跨文档。两种做法都能用，但都要求在标注数据上验证混淆矩阵，不能只看端到端准确率。

路由带来的收益容易被误判。准确率上升可能只是因为某类查询走了更好的配置，而如果只看总体数字，就无法知道是哪一类改善了，也不容易发现某类查询反而退化。评测必须按查询类型分层报告，并且把每一类的样本量写清楚。样本量小的那一类，即使准确率大幅波动也不具备统计意义。
