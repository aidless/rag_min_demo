# 工具与外部接口

工具和外部接口进入检索链路时会带来新的误差源，因为它们把检索的结果依赖从库内扩展到了库外，库内的评测无法覆盖这一部分。接口返回的内容会随时间变化，同一个查询昨天和今天返回不同，昨天的评测数字今天就不可复现。要让这类评测有意义，必须在评测时固定接口响应，把真实响应存档并让测试读取存档，否则每次跑出来的差异都分不清是系统改进还是外部数据变了。存档本身带来一个问题：存档过期后评测仍然会报一个好看的旧数字，掩盖线上正在发生的变化。

工具调用的失败率和延迟都远高于库内检索，而且失败模式不唯一：参数格式错误、权限不足、超时、返回空结果、返回结果但语义不相关，每一种都需要不同的处理。空结果和语义不相关的处理最容易出错——前者通常被当作失败重试，实际上它可能是正确答案就是"没有"，重试只是浪费时间并压低吞吐；后者被当作成功接受，于是错误答案直接进入生成环节。工具描述的准确性直接决定调用质量，描述含糊时模型会频繁调错参数，而这种错误在总准确率里表现为一个说不清来源的下降。

工具数量本身是一个限制。超过二十个之后，模型的工具选择准确率明显下降，调用顺序也容易出错。应对方式不是继续加工具，而是合并同类工具、用更清晰的命名和描述降低混淆，并在工具集合上单独做一次选择准确率评测。检索链路里引入外部接口之后，延迟的构成也随之改变，接口延迟通常远大于库内检索，多工具串联调用会让总延迟翻数倍，任何一个接口的抖动都会传导到最终结果。
